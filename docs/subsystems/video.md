# Video generation

English | [中文](video.zh.md)

The video seam — a [capability seam](../glossary.md#capability-seam) exposing text-to-video generation on one `ctx.video` service, split across packages: Service Definition ([dsh-video](../../packages/video/video), `ctx.video` + the provider registry), Service Provider ([dsh-video-wuyinkeji](../../packages/video/video-wuyinkeji) and [dsh-video-volc](../../packages/video/video-volc) — the former submits to the Wuyinkeji video task endpoint its configured `model` selects (Google-Omni, MiniMax H3, or Grok Imagine), the latter posts a chat-completions-shaped task to the Volcengine Ark inference plane and can register reference images as private Seedance assets; one provider claims the seam, and its endpoint, model, and credential are deployment-owned), and Consumer ([dsh-tool-video](../../packages/video/tool-video), the model-facing `generate_video` tool schema). Video generation is **one optional capability**, not part of the agent-loop spine. A provider swap does not change how callers or the model use the seam; with no provider registered, every generation throws `VideoError` `VIDEO_UNAVAILABLE` and the tool answers with an actionable unavailable message. DSH never selects a generation model at runtime — the provider's `model` configuration does.

Source: [`packages/video/video/src/types.ts`](../../packages/video/video/src/types.ts)

## Operations and generated videos

One operation shares the seam: `generate` receives a `VideoGenerateRequest` — a required text `prompt`, optional `size`, `duration`, and `aspectRatio` refinements, and `firstFrame`, `lastFrame`, `referenceImage`, `referenceVideo`, and `referenceAudio` reference URLs (publicly reachable; providers that do not accept a refinement ignore it) — and returns a `VideoResult`, the raw video `data` bytes with the `mediaType` they decode as. The seam sets no timeout or size cap; those budgets belong to the consumer, and the endpoint timeout belongs to the provider. Consumers durably commit the generated bytes through the attachment service before referencing them in any session content.

Providers register under an opaque identity string reserved atomically at registration; `VideoError` extends `HarnessError` with stable codes `VIDEO_INVALID_PROVIDER`, `VIDEO_CONFLICT`, `VIDEO_UNAVAILABLE`, `VIDEO_DISPOSED`, `VIDEO_INVALID_REQUEST`, and `VIDEO_PROVIDER_FAILED`, which callers route on instead of parsing `message`.

### `ctx.video` — `VideoService`

The `ctx.video` surface: a single-provider reservation registry plus the routed `generate` operation. The seam exposes no protocol escape hatch — endpoint shape, model, and credentials are the provider's private concern.
