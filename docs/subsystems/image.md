# Image generation

English | [中文](image.zh.md)

The image seam — a [capability seam](../glossary.md#capability-seam) exposing text-to-image generation on one `ctx.image` service, split across packages: Service Definition ([dsh-image](../../packages/image/image), `ctx.image` + the provider registry), Service Provider ([dsh-image-http](../../packages/image/image-http), an OpenAI-compatible `/images/generations` HTTP client whose endpoint, model, and credential are deployment-owned), and Consumer ([dsh-tool-image](../../packages/image/tool-image), the model-facing `generate_image` tool schema). Image generation is **one optional capability**, not part of the agent-loop spine. A provider swap does not change how callers or the model use the seam; with no provider registered, every generation throws `ImageError` `IMAGE_UNAVAILABLE` and the tool answers with an actionable unavailable message. DSH never selects a generation model — the provider owns the endpoint and its model outright.

Source: [`packages/image/image/src/types.ts`](../../packages/image/image/src/types.ts)

## Operations and generated images

One operation shares the seam: `generate` receives an `ImageGenerateRequest` — a required text `prompt` plus optional `size` and `n` refinements — and returns an `ImageResult`, the raw image `data` bytes with the `mediaType` they decode as and an optional provider-reported `revisedPrompt`. The seam sets no timeout or size cap; those budgets belong to the consumer, and the endpoint timeout belongs to the provider. Consumers durably commit the generated bytes through the attachment service before referencing them in any session content.

Providers register under an opaque identity string reserved atomically at registration; `ImageError` extends `HarnessError` with stable codes `IMAGE_INVALID_PROVIDER`, `IMAGE_CONFLICT`, `IMAGE_UNAVAILABLE`, `IMAGE_DISPOSED`, `IMAGE_INVALID_REQUEST`, and `IMAGE_PROVIDER_FAILED`, which callers route on instead of parsing `message`.

### `ctx.image` — `ImageService`

The `ctx.image` surface: a single-provider reservation registry plus the routed `generate` operation. The seam exposes no protocol escape hatch — endpoint shape, model, and credentials are the provider's private concern.
