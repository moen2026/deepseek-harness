# image/ — Image generation for agents

English | [中文](README.zh.md)

## Summary

The image group lets agents create images from text prompts: `generate_image` sends the prompt to the provider, durably commits the generated bytes as an image attachment, and returns the image itself beside a bounded text envelope. Back the seam with `image-http` (an OpenAI-compatible `/images/generations` endpoint) or `image-wuyinkeji` (Wuyinkeji's async task API: GPT-Image-2.5 or NanoBanana2Lite via `model`); URL, model, and credential stay deployment-owned. `tool-image` exposes generation to the model. The shared `image` package keeps request and result vocabulary provider-neutral, so swapping providers does not change model requests. The group ships no generation engine and answers nothing without a mounted provider.

## Packages

| Package | Role | ctx key |
|---|---|---|
| [`image/`](image/README.md) | Defines the image service: an exclusive single-provider reservation and one order-independent route (generate) | `ctx.image` |
| [`image-http/`](image-http/README.md) | Posts text prompts to a deployment-named OpenAI-compatible endpoint and maps the answer onto the seam's image result | registers on `ctx.image` |
| [`image-wuyinkeji/`](image-wuyinkeji/README.md) | Submits text prompts to the Wuyinkeji async task endpoint `model` selects (GPT-Image-2.5 or NanoBanana2Lite), polls the task until settlement, and downloads the settled image URL into raw bytes | registers on `ctx.image` |
| [`tool-image/`](tool-image/README.md) | Exposes generation to the model through `generate_image` over the attachment store | registers on `ctx.tools` |

Providers post prompts and speak endpoint protocols, not tools: `tool-image` is the only owner of the model-facing name, schema, prompt guidance, and presentation, so swapping a provider never changes how the model asks for an image.
