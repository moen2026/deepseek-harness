# @deepseek-ai/dsh-tool-image

English | [中文](README.zh.md)

## Summary

`dsh-tool-image` gives a model one tool over `ctx.image`: `generate_image` sends a text prompt (plus optional size and reference-image hints) to the reserved provider, durably commits the generated bytes as an image attachment, and returns the image beside a bounded text envelope, so model and user both see what was created. Without a mounted provider it returns an actionable "image unavailable" message instead of failing the session. A media type the deployment cannot store surfaces as an actionable error before anything enters durable history. The package runtime-injects only `tools`, `image`, and `systemPrompt` and imports no provider.

<a id="use-this-package"></a>
## Use this package

A model calls `generate_image` when the user asks for an illustration, a mockup, or any picture a text prompt can describe; the tool's prompt guidance tells it to continue without generation when the capability is not configured.

### The tool

`generate_image` takes a required `prompt` plus an optional `size` (for example `"1024x1024"`) and optional `referenceImages` (publicly reachable URLs of reference images guiding the generation, for image-to-image). It trims its inputs, drops blank refinements, and rejects a blank `prompt`, a non-string `size`, or a malformed `referenceImages` list as an actionable argument error before touching the seam. A provider that does not accept reference images ignores them. Provider choice, endpoint, credential, and model stay outside model input; they belong to the mounted provider.

### What the model gets back

The tool returns a closed result: `status` `ok` with `image` (the durable attachment reference — `attachmentId`, `mediaType`, `bytes`, `width`, `height`, optional `name`) and an optional provider-reported `revisedPrompt`, or `unavailable`. Rendering emits the image block itself beside a `<type>image</type>` envelope naming the media type, dimensions, and byte count, plus the revised prompt when the provider reports one, bounded by `maxResultChars`. When no provider is mounted, the render is the actionable unavailable message instead of an error.

### Configuration

| Key | Default | Meaning |
|---|---|---|
| `maxResultChars` | `8000` | Largest complete rendered envelope, including any truncation |
| `timeoutMs` | `180000` | Tool-call timeout budget, covering one generation round trip |

The generated [configuration catalog](../../../docs/config-catalog.md#deepseek-aidsh-tool-image) is the exhaustive source for every accepted field.

### Failures and recovery

No mounted attachment store returns `status: 'unavailable'` before any generation I/O, so a refusal never spends the caller's provider budget. An `IMAGE_UNAVAILABLE` from the seam is caught and returned as `status: 'unavailable'` so the session keeps running. A media type outside the deployment's storable set (PNG/JPEG/WebP/GIF) throws an actionable error naming the offending type; any other `ImageError` (a provider failure, an invalid request) propagates as a structured tool error the model can read and route on.

## Understand the implementation

<details>
<summary>Implementation internals — click to expand</summary>

This section explains the design decisions behind the tool and where the code realizes them; observable behavior is covered in [Use this package](#use-this-package).

### Design notes

- **Consumer-only.** The tool runtime-injects only `tools`, `image`, and `systemPrompt`, imports no provider, and passes only `exec.signal` to the seam.
- **Gate before spend.** The attachment store is checked before the generate call, so a deployment that cannot durably commit bytes never pays for generation.
- **Persist before return.** The image is committed through `attachments.saveImage()` before the tool result is built, so the image block always references a durably committed object by the time the tool/result event is appended.
- **Argument normalization before the seam.** `parseGenerateImageArgs` trims and collapses inputs, so the provider receives a canonical request and malformed input is an actionable error rather than a crash.
- **Availability is data, not a crash.** `execute` catches `ImageError` with code `IMAGE_UNAVAILABLE` and returns an `unavailable` status; every other error rethrows, so a genuinely broken provider is still surfaced.
- **Bounded render.** `formatGeneratedImage` caps what enters the conversation; the image bytes themselves ride the adjacent image block and never enter the text envelope.
- **Concurrency-safe generation.** `generate_image` returns `isConcurrencySafe: () => true` — generation is stateless and content-addressed attachment writes are idempotent.
- **Generic card presentation.** `presentGenerateImageCall` renders `{ card: 'generic', kind: 'other', title }` titled with a bounded prompt label that appends the reference-image count.

### Source map

| File | Role |
|---|---|
| [`src/index.ts`](src/index.ts) | Plugin entry: config schema, prompt section, `generate_image` registration and execution |
| [`src/render.ts`](src/render.ts) | Pure argument validation, generated-image envelope with result caps, UI presentation |
| — | No runtime invariant companion is published; this stateless adapter contributes one tool and one prompt section, while provider lifecycle stays owned by the image seam it composes. |

## Model Experience

### System prompt

#### What the model sees

One system-prompt section (first-party order 2456) positions the generation tool and its optionality with the following text:

##### Verbatim guidance

```markdown
Use generate_image to create an image from a text prompt. It is unavailable until an image provider is configured — then continue without image generation, for example by suggesting the user configure one.
```

#### Token effect

Fixed guidance cost on every request while the plugin is active.

#### KV Cache effect

Prefix-stable while the plugin scope and guidance text are unchanged; activation or disposal may invalidate reuse from this section.

### Tool schema

#### What the model sees

The model sees the generated [`generate_image` schema](../../../docs/tool-catalog.md#deepseek-aidsh-tool-image).

#### Token effect

Fixed schema cost on every request while enabled; the `timeoutMs` budget is never sent to the model.

#### KV Cache effect

Prefix-stable while the visible tool definition and order are unchanged; registration lifecycle or scoped restrictions may invalidate reuse from the first changed schema token.

### Results

#### What the model sees

An ok result renders the image block itself (the generated picture) beside a `<type>image</type>` envelope naming the media type, dimensions, and byte count, plus the provider's `revisedPrompt` when reported, bounded by `maxResultChars`. When no provider is mounted, the result is the actionable unavailable message instead of an error.

#### Token effect

The envelope is capped by `maxResultChars`; the image itself rides the image block, not the text.

#### KV Cache effect

Tool results append after the cached request prefix and do not directly invalidate it.

### UI presentation

#### What the model sees

Nothing. The client renders a generic card — `{ card: 'generic', kind: 'other', title }` — titled `Generate image: <prompt label>`, appending the reference-image count when the request carries reference images; the image itself is rendered through the tool-owned image slot like `read_image` results.

#### Token effect

Zero direct token effect because rendering is client-side only.

#### KV Cache effect

None; UI presentation is outside the model request.

## Known Limitations and Deferred Work

<a id="known-limitations-and-deferred-work"></a>


These limits define when the tool is a poor fit. They are current package constraints, not a task backlog.

- **Provider-gated availability** — with no image provider mounted the tool always returns the unavailable message; it never generates anything itself, so a deployment must mount `dsh-image-http` (or another provider) for real images.
- **Store-gated persistence** — without a mounted attachment store the tool returns the unavailable answer before generating, so the generated bytes always have a durable home.
- **Provider-dependent reference images** — the tool passes `referenceImages` through as a request field; whether an endpoint accepts them is the mounted provider's policy, and a provider that does not accept reference images does not send them.
- **One image per call** — a multi-image request is several calls; the result models a single attachment.
