# @deepseek-ai/dsh-tool-video

English | [中文](README.zh.md)

## Summary

`dsh-tool-video` gives a model one tool over `ctx.video`: `generate_video` sends a text prompt (plus optional size, duration, aspect-ratio, frame-conditioning, and reference-media hints) to the reserved provider, durably commits the generated bytes as a file attachment, and returns the file beside a bounded text envelope, so model and user both see what was created. Without a mounted provider it returns an actionable "video unavailable" message instead of failing the session. A media type the deployment cannot store surfaces as an actionable error before anything enters durable history. The package runtime-injects only `tools`, `video`, and `systemPrompt` and imports no provider.

<a id="use-this-package"></a>
## Use this package

A model calls `generate_video` when the user asks for a clip, a shot, or any motion a text prompt can describe; the tool's prompt guidance tells it to continue without generation when the capability is not configured.

### The tool

`generate_video` takes a required `prompt` plus an optional `size` (for example `"1280x720"`), an optional `duration` in seconds, an optional `aspectRatio` (for example `"16:9"` or `"adaptive"`), and optional `firstFrame`, `lastFrame`, `referenceImage`, `referenceVideo`, and `referenceAudio` (publicly reachable URLs of frame-conditioning images or reference media guiding the generation). It trims its inputs and rejects a blank `prompt`, a blank `size`, a non-positive-integer `duration`, or a blank reference URL as an actionable argument error before touching the seam. Provider choice, endpoint, credential, and model stay outside model input; they belong to the mounted provider.

### What the model gets back

The tool returns a closed result: `status` `ok` with `video` (the durable attachment reference — `attachmentId`, `name`, `bytes`, `mediaType`) or `unavailable`. Rendering emits the file block itself beside a `<type>video</type>` envelope naming the media type and byte count, bounded by `maxResultChars`. When no provider is mounted, the render is the actionable unavailable message instead of an error.

### Configuration

| Key | Default | Meaning |
|---|---|---|
| `maxResultChars` | `8000` | Largest complete rendered envelope, including any truncation |
| `timeoutMs` | `660000` | Tool-call timeout budget, covering one generation round trip |

The generated [configuration catalog](../../../docs/config-catalog.md#deepseek-aidsh-tool-video) is the exhaustive source for every accepted field.

### Failures and recovery

No mounted attachment store returns `status: 'unavailable'` before any generation I/O, so a refusal never spends the caller's provider budget. A `VIDEO_UNAVAILABLE` from the seam is caught and returned as `status: 'unavailable'` so the session keeps running. A media type outside the deployment's storable set (MP4/WebM/MOV) throws an actionable error naming the offending type; any other `VideoError` (a provider failure, an invalid request) propagates as a structured tool error the model can read and route on.

## Understand the implementation

<details>
<summary>Implementation internals — click to expand</summary>

This section explains the design decisions behind the tool and where the code realizes them; observable behavior is covered in [Use this package](#use-this-package).

### Design notes

- **Consumer-only.** The tool runtime-injects only `tools`, `video`, and `systemPrompt`, imports no provider, and passes only `exec.signal` to the seam.
- **Gate before spend.** The attachment store is checked before the generate call, so a deployment that cannot durably commit bytes never pays for generation.
- **Persist before return.** The video is committed through `attachments.saveFile()` before the tool result is built, so the file block always references a durably committed object by the time the tool/result event is appended.
- **Argument normalization before the seam.** `parseGenerateVideoArgs` trims and normalizes inputs, so the provider receives a canonical request and malformed input is an actionable error rather than a crash.
- **Availability is data, not a crash.** `execute` catches `VideoError` with code `VIDEO_UNAVAILABLE` and returns an `unavailable` status; every other error rethrows, so a genuinely broken provider is still surfaced.
- **Bounded render.** `formatGeneratedVideo` caps what enters the conversation; the video bytes themselves ride the adjacent file block and never enter the text envelope.
- **Concurrency-safe generation.** `generate_video` returns `isConcurrencySafe: () => true` — generation is stateless and content-addressed attachment writes are idempotent.
- **Generic card presentation.** `presentGenerateVideoCall` renders `{ card: 'generic', kind: 'other', title }` titled with a bounded prompt label that appends size, duration, aspect-ratio, and reference-media notes.

### Source map

| File | Role |
|---|---|
| [`src/index.ts`](src/index.ts) | Plugin entry: config schema, prompt section, `generate_video` registration and execution |
| [`src/render.ts`](src/render.ts) | Pure argument validation, generated-video envelope with result caps, UI presentation |
| — | No runtime invariant companion is published; this stateless adapter contributes one tool and one prompt section, while provider lifecycle stays owned by the video seam it composes. |

## Model Experience

### System prompt

#### What the model sees

One system-prompt section (first-party order 2458) positions the generation tool and its optionality with the following text:

##### Verbatim guidance

```markdown
Use generate_video to create a video from a text prompt. It is unavailable until a video provider is configured — then continue without video generation, for example by suggesting the user configure one.
```

#### Token effect

Fixed guidance cost on every request while the plugin is active.

#### KV Cache effect

Prefix-stable while the plugin scope and guidance text are unchanged; activation or disposal may invalidate reuse from this section.

### Tool schema

#### What the model sees

The model sees the generated [`generate_video` schema](../../../docs/tool-catalog.md#deepseek-aidsh-tool-video).

#### Token effect

Fixed schema cost on every request while enabled; the `timeoutMs` budget is never sent to the model.

#### KV Cache effect

Prefix-stable while the visible tool definition and order are unchanged; registration lifecycle or scoped restrictions may invalidate reuse from the first changed schema token.

### Results

#### What the model sees

An ok result renders the file block (the generated video as a durable attachment) beside a `<type>video</type>` envelope naming the media type and byte count, bounded by `maxResultChars`. When no provider is mounted, the result is the actionable unavailable message instead of an error.

#### Token effect

The envelope is capped by `maxResultChars`; the video itself rides the file block, not the text.

#### KV Cache effect

Tool results append after the cached request prefix and do not directly invalidate it.

### UI presentation

#### What the model sees

Nothing. The client renders a generic card — `{ card: 'generic', kind: 'other', title }` — titled `Generate video: <prompt label>`, appending size, duration, aspect-ratio, and reference-media notes when present; the settled result's file block draws the durable file chip the message stream uses, labelled with the file name, extension, and byte size.

#### Token effect

Zero direct token effect because rendering is client-side only.

#### KV Cache effect

None; UI presentation is outside the model request.

## Known Limitations and Deferred Work

<a id="known-limitations-and-deferred-work"></a>


These limits define when the tool is a poor fit. They are current package constraints, not a task backlog.

- **Provider-gated availability** — with no video provider mounted the tool always returns the unavailable message; it never generates anything itself, so a deployment must mount `dsh-video-wuyinkeji` (or another provider) for real videos.
- **Store-gated persistence** — without a mounted attachment store the tool returns the unavailable answer before generating, so the generated bytes always have a durable home.
- **Provider-dependent reference media** — the tool passes the frame-conditioning and reference-media URLs through as request fields; whether an endpoint accepts them is the mounted provider's policy.
- **One video per call** — the result models a single file attachment.
